# LAST LOG : 마지막 접속

2010 년대 인터넷 단체 채팅방을 배경으로 한 **협동 라이브 추리 게임**. 최대 12 명이 방 코드 하나로 같은 사건에 들어와, NPC 취조는 각자 나눠 맡고 단서·수첩·추리 보드·채팅은 실시간으로 함께 쓴다. 1989 년식 CRT 모니터 바탕화면 컨셉. 모든 대사는 미리 작성된 키워드 반응형(실시간 AI 없음).

겉으로는 실종 사건이지만, 파고 들면 실종자가 연쇄살인범이고 남은 사람들은 그의 알리바이에 이용됐다는 것이 드러난다. 스포일러가 포함된 스토리 설계는 `STORY.md`에 있다.

## 플레이 흐름

1. **로비** — 닉네임 입력 → "새 방 만들기"(방장) 또는 6 자리 방 코드로 "참가". 탭 하나가 플레이어 한 명이다.
2. **moi.net — 채팅방 두 개.** "새벽 2 시"는 NPC(고니·계룡맛·오이오이·wkwkdfoq·호호19·포청천)가 듣는 방이다. 플레이어끼리 대화하고, NPC가 키워드에 끼어들며, 조건이 맞으면 이벤트가 터진다. **"수사실"은 플레이어만 있는 방**이다. NPC는 보지 못하고 반응하지 않는다. 누구를 의심하는지는 수사실에서 말하는 것이 안전하다 — 새벽 2 시 방에서 실종자를 범인으로 모는 말은 **보고 있는 누군가에게 새어 나가** DAY 4에 그대로 인용된다. 닉네임을 입력하면 그 NPC와의 **1:1 취조**로 전환된다(취조 기록은 본인만 봄).
3. **공유 단서** — 누가 무엇을 알아내든 즉시 방 수첩에 기록되고 그룹채팅에 "📎 ○○ — 단서 제목"으로 뜬다. **신뢰도는 방 단위**: 남이 알아낸 사실이 내 취조의 잠금을 푼다.
4. **증거 제시** — 1:1 취조 아래 메뉴에서 방 수첩의 단서를 골라 상대에게 보여 준다. 전용 반응 + 새 단서.
5. **검색** — 검색엔진 화면처럼 결과가 뜬다(제목 · 주소 · 맞은 낱말이 굵게 표시된 요약, 관련도순, 최대 8 건). 결과를 클릭하면 **팝업 창**에 그 기록이 실제 2010 년대 웹페이지처럼 열린다: 블로그 글, 커뮤니티 글과 댓글, 접속 로그 표, 메신저 스크린샷, 뉴스/신고 기록, 사진(EXIF 포함). **페이지를 열어야 단서로 기록**되고, 팝업의 "새벽 2 시에 공유"/"수사실에 공유"로 링크를 올리면 다른 사람도 눌러서 같은 페이지를 볼 수 있다. 결과가 전부 사실은 아니다(가짜 단서 5 개, 관련자에게 제시하면 반박됨). 검색 결과가 없으면 오타 제안("이것을 찾으셨나요?")과 그날의 실시간 검색어가 뜬다. 한 글자·두 글자로 찍어서 훨씬 긴 낱말을 끌어오는 건 막혀 있다. 처음 연 결과와 남이 먼저 열어 이미 방 수첩에 있는 결과는 다르게 표시된다(각각 방문 표시·NEW 배지). 수첩의 검색 단서에는 "페이지 열기" 링크가 있다.
6. **추리 보드** — Obra Dinn + Golden Idol 방식의 **공유 보드**. DAY 2~4는 보드가 두 개(A를 다 잠그면 B가 열린다)이고, 날마다 빈칸 문장 4~7 개가 있고, 빈칸에 끼울 **조각은 방 수첩에 단서가 모일 때만 생긴다** (인물 이름만 처음부터 있음). 조각 트레이는 실시간으로 늘어나지만, **무엇이 조각인지는 채팅에 알려 주지 않는다** — 오브라딘처럼 스스로 추리 보드를 열어 확인해야 한다("📎 기록됨"만 중립적으로 뜬다). 조각을 누르면 빈칸에 끼워지고(칸을 먼저 누르면 그 칸에), 누가 끼웠는지 표시되며 실시간 공유된다. 가짜 단서도 조각을 만든다("해커", "승합차 운전자"). "확인"은 어느 칸이 틀렸는지 알려 주지 않고, 맞은 칸이 3 개 이상 동시에 있어야 잠긴다. 보드를 다 잠그면 정리 단서 + 그룹채팅 반응.
7. **다음 날** — 그날 보드(A와 B)가 전부 완성되면 **방장**이 `오늘은 여기까지`로 넘긴다(방장이 2 분 이상 자리를 비우면 누구나 가능). DAY 3 밤에는 방 안에서 한 명이 사라지고, DAY 4부터 그 사람은 취조할 수 없다 — 남긴 것을 검색으로 찾아야 한다. DAY 5까지.
8. **최종 추리** — 10 칸짜리 마지막 보드. 방 전체가 함께 완성하면 **경찰에 알릴 한 사람을 지목**한다(방 전체에 적용). 진범을 지목하면 TRUE END(검거), NPC를 지목하면 BAD END. TRUE END에 더해 보고 있던 계정까지 특정하고 찾은 가짜 단서를 전부 반박했으면 PERFECT.

채팅창 명령어: `닉네임`, `새벽 2 시`(그룹채팅), `수사실`, `검색 ○○`, `대화기록`, `대화검색 ○○`, `증거 ○○`, `목표`, `힌트`, `정리해줘`, `방 정보`, `나가기`, `오늘은 여기까지`.

**대화 기록** — NPC와 그룹채팅의 대사는 전부 키워드에 반응해 자동으로 나온다(실시간 AI 없음). 그 자동 대사가 정확히 언제 뭐라고 나왔는지는 바탕화면의 "대화 기록"(또는 `대화기록`, `대화검색 ○○` 명령)에서 다시 찾아볼 수 있다. 새벽 2 시·수사실은 방 전체가 공유하고, 1:1 취조 기록은 각자 자기 화면에만 남는다.

## 구조

- `index.html` / `style.css` — CRT 데스크톱 UI + 로비
- `data.js` — 게임 데이터: NPC 대사 540 개, 검색 단서 ~70 + 가짜 5, 증거 반응 ~170, 그룹 반응/이벤트, 추리 보드 8 개(A 4 + B 3 + 최종), 미해결 의문. 맨 아래 `v2` 블록이 연쇄살인범 반전(과거 사건, 포청천의 밤, 헨델, 결말)을 얹는다
- `script.js` — 게임 로직 + 방/동기화 (전부 브라우저에서 동작)
- `store.js` — 동기화 계층. Firebase Realtime Database가 있으면 그걸 쓰고, 없으면 같은 브라우저 탭끼리만 동기화되는 로컬 모드
- `database.rules.json` — Realtime Database 보안 규칙 (`rooms/<코드>` 아래만 읽기/쓰기 허용). 수사실 대화는 `rooms/<코드>/private`에 저장된다

## 배포 / 설정

Hosting은 `main`에 push하면 GitHub Actions가 자동 배포한다. **여러 기기에서 같은 방에 들어오려면 딱 한 가지 설정이 필요하다** (브라우저에서만):

1. Firebase 콘솔 → 프로젝트 `moi-net` → 빌드 → **Realtime Database** → "데이터베이스 만들기" → 위치는 아무거나(예: 싱가포르) → **테스트 모드**로 시작.
2. 끝. 다음 push부터 GitHub Actions가 `database.rules.json`을 자동 배포해 테스트 모드 규칙을 대체한다. (이미 push된 상태라면 GitHub → Actions 탭에서 최근 워크플로 "Re-run all jobs".)

설정 전에는 사이트 로비에 "로컬 모드"라고 표시되고, 같은 브라우저의 탭끼리만 동기화된다. 설정 후에는 "실시간 서버 연결됨"으로 바뀐다. Firebase 설정값(apiKey 등)은 Hosting이 자동으로 제공하는 `/__/firebase/init.js`에서 받아오므로 코드에 붙여 넣을 것이 없다. Spark(무료) 플랜으로 충분하다.
